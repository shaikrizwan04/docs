---
title: "Internal Transactions with Advanced Directional Filtering"
sidebarTitle: "Advanced txlistinternal"
description: "Filter internal transactions by sender and/or recipient address using AND/OR logic, or query all internal transactions across a block range."
---

The Advanced Filter variant of the internal transactions endpoint lets you filter internal calls by `from` and `to` address with explicit AND/OR logic — the same directional filtering available for normal and token transactions. Alternatively, provide `startblock` and `endblock` without any address filter to retrieve all internal transactions across a block range. This is useful for tracking ETH movements between specific contracts, identifying fund flows through intermediary contracts, or scanning for internal calls to or from a known address.

<Note>
  This is a **PRO endpoint**, available on the [Standard Plan](/rate-limits) and above. It is currently in **Beta** — behavior may change.
</Note>

<Tip>
  Explore and preview data interactively using the [Advanced Filter](https://etherscan.io/advanced-filter) page on Etherscan before integrating this endpoint.
</Tip>

## Parameters

<ParamField query="chainid" type="string" required>
  The chain ID to query. Use `1` for Ethereum mainnet or any chain from the [supported chains](/supported-chains) list.
</ParamField>

<ParamField query="module" type="string" required default="account">
  Set to `account` for this endpoint.
</ParamField>

<ParamField query="action" type="string" required default="txlistinternal">
  Set to `txlistinternal` for this endpoint.
</ParamField>

<ParamField query="from" type="string">
  Filter internal calls by sender address. Provide `from`, `to`, or both — or use `startblock` + `endblock` instead.
</ParamField>

<ParamField query="to" type="string">
  Filter internal calls by recipient address. Provide `from`, `to`, or both — or use `startblock` + `endblock` instead.
</ParamField>

<ParamField query="fromto_opr" type="string">
  Required when `from` or `to` is provided. Use `and` to require both addresses to match, or `or` to match calls where either address matches.
</ParamField>

<ParamField query="startblock" type="integer" default="0">
  Starting block number to search from.
</ParamField>

<ParamField query="endblock" type="string" default="latest">
  Ending block number to search to. Use `latest` for the current block.
</ParamField>

<ParamField query="page" type="integer" default="1">
  Page number for pagination.
</ParamField>

<ParamField query="offset" type="integer" default="10">
  Number of records per page.
</ParamField>

<ParamField query="sort" type="string" default="desc">
  Sort order. Use `asc` for oldest first, `desc` for latest first.
</ParamField>

<ParamField query="apikey" type="string" required>
  Your Etherscan API key. [Set one up](/set-up-your-api-key) if you don't have one.
</ParamField>

## Response

<ResponseField name="status" type="string">
  `1` if the request returned data, `0` otherwise.
</ResponseField>

<ResponseField name="message" type="string">
  `OK` on success. See [common error messages](/common-error-messages) for error values.
</ResponseField>

<ResponseField name="result" type="array">
  An array of internal transaction objects matching the filter criteria.

  <Expandable title="result[]">
    <ResponseField name="blockNumber" type="string">Block number in which the parent transaction was included.</ResponseField>
    <ResponseField name="timeStamp" type="string">Time the block was mined, as a UNIX timestamp in seconds.</ResponseField>
    <ResponseField name="hash" type="string">Hash of the parent transaction that triggered this internal call.</ResponseField>
    <ResponseField name="from" type="string">Address that initiated the internal call.</ResponseField>
    <ResponseField name="to" type="string">Recipient address. Empty for contract-creation internal calls.</ResponseField>
    <ResponseField name="value" type="string">Amount of the native token transferred, in wei.</ResponseField>
    <ResponseField name="contractAddress" type="string">Address of any contract created by this internal call. Empty otherwise.</ResponseField>
    <ResponseField name="input" type="string">Input data of the internal call, as a hex string.</ResponseField>
    <ResponseField name="type" type="string">Type of internal call: `call`, `create`, `create2`, or `selfdestruct`.</ResponseField>
    <ResponseField name="gas" type="string">Gas forwarded to this internal call.</ResponseField>
    <ResponseField name="gasUsed" type="string">Gas actually consumed by this internal call.</ResponseField>
    <ResponseField name="traceId" type="string">Position of this internal call in the transaction's execution trace.</ResponseField>
    <ResponseField name="isError" type="string">`0` if the call succeeded, `1` if it failed.</ResponseField>
    <ResponseField name="errCode" type="string">Error code if the call failed. Empty on success.</ResponseField>
  </Expandable>
</ResponseField>

## Example

This example fetches all internal transactions that called a specific address, using the `or` operator with only a `to` filter.

<CodeGroup>
```bash cURL
curl "https://api.etherscan.io/v2/api\
?chainid=1\
&module=account\
&action=txlistinternal\
&to=0x2c1ba59d6f58433fb1eaee7d20b26ed83bda51a3\
&fromto_opr=or\
&startblock=0\
&endblock=latest\
&page=1\
&offset=10\
&sort=desc\
&apikey=YOUR_API_KEY"
```

```python Python
import requests

params = {
    "chainid": "1",
    "module": "account",
    "action": "txlistinternal",
    "to": "0x2c1ba59d6f58433fb1eaee7d20b26ed83bda51a3",
    "fromto_opr": "or",
    "startblock": 0,
    "endblock": "latest",
    "page": 1,
    "offset": 10,
    "sort": "desc",
    "apikey": "YOUR_API_KEY",
}

response = requests.get("https://api.etherscan.io/v2/api", params=params)
print(response.json())
```
